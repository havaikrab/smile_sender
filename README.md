# Smile Sender  

## Описание:
Smile Sender - это проект, созданный в рамках обучения языку программирования Python.   
Smile Sender - сервис рассылок электронных писем, реализованный на базе фреймворка Django.  

## Цель проекта:
Главной целью Smile Sender является закрепление полученных знаний и навыков работы с фреймворком Django.  
А также повторение материала предыдущих уроков, и применение всех полученных знаний на практике, то есть, для решения  
задач, приближенных к реальным.  

## Установка:
1. Запустите IDE на локальном ПК.  

2. Клонируйте Sky Store из удаленного репозитория.  
Для этого можно из текущей директории на вашем ПК ввести в терминале команду:  
git clone git@github.com:havaikrab/smile_sender.git  

3. Установите зависимости.  
В проекте используется менеджер зависимостей Poetry, установите его, при необходимости.
Для установки зависимостей введите в терминале команду: poetry install  

4. Для работы приложения используется СУБД PostgreSQL, для запуска сервера приложения
ее необходимо установить "вручную", создать базу данных и указать все необходимые настройки
для подключения к ней в файле .env в корне проекта.  

5. В файле .env_template представлен шаблон с необходимыми настройками проекта, многие настройки имеют значения по умолчанию,
однако, их переопределение позволит лучше адаптировать программу под конкретные условия.  

5. Для кеширования в проекте используется брокер redis. Перед запуском сервера необходимо запустить брокер кеширования.  

6. Для эффективной работ сервера рекомендуется запускать его в ОС Linux, так как в проекте используется
инструмент Celery, не поддерживаемый на Windows.  


## Запуск:
Активируйте виртуальное окружение.  

Примените миграции с помощью команды python manage.py migrate.  

Управление сервисом осуществляет группа пользователей-менеджеров. Для оперативного создания группы с необходимыми
правами доступа рекомендуется выполнить команду python manage.py create_managers_group.  

Создайте супер-пользователя с помощью команды python manage.py createsuperuser. Это необходимо сделать, так как только
супер-пользователь имеет право назначать и снимать с должности менеджеров сервиса. При создании
суперпользователя в атрибуте <is_active> нужно указать <True>, иначе данный пользователь не сможет авторизоваться.

Запустите сервер приложения с помощью команды python manage.py runserver.  
После этого в браузере введите адрес localhost:8000 и вы попадете на главную страницу сервиса.  
При запуске на ОС Linux ключ USE_CELERY в файле .env_template рекомендуется указать значение <true>, что позволит
приложению работать более корректно. А именно, Celery позволяет запускать рассылки писем в фоновом режиме,
в то время как пользователь будет совершать другие действия на сайте. При НЕ-использовании Celery
процесс рассылки также запускается, однако наблюдается эффект "зависания" страницы, что может ввести
пользователя в заблуждение, так как долго не происходит автоматический редирект на "следующую" страницу.
В таком случае, мало вероятно, но, после запуска рассылки пользователь может дождаться автоматического редиректа,
который произойдет только после отправки всех писем, или принудительно открыть другую страницу.  В обоих случаях рассылка
будет продолжать выполняться, пока не завершится или не будет прервана пользователем.  

## Права доступа  
После запуска сервера, посетители могут посещать сайт, но неавторизованным пользователям будет доступна только главная страницы
приложения с небольшой общей статистикой. После регистрации пользователь также должен подтвердить подлинность своего email,
для этого он должен перейти по ссылке активации, направленной на указанный им email. После активации аккаунта пользователь
сможет авторизоваться и полноценно пользоваться сервисом. При создании супер-пользователя активация аккаунта происходит
при указании атрибута <is_active> -> True. Обычный авторизованный пользователь может управлять своими рассылками, списком
собственных получателей, и собственными текстами рассылок. Пользователям, состоящим в группе менеджеров дополнительно открывается
возможность просматривать общий список получателей, сохраненных в базе данных приложения. А также пользователь-менеджер может
принудительно завершать рассылки и блокировать/разблокировать аккаунты других пользователей. При блокировке аккаунта, пользователь
теряет возможность запускать собственные рассылки и для разблокировки должен обратиться к администрации сервиса.
Как упоминалось выше, супер-пользователь имеет право добавлять или исключать других пользователей из группы менеджеров,
помимо этого, ему также доступен функционал менеджеров.
По мере дальнейшей разработки аналогично группе менеджеров могут быть реализованы другие группы пользователей, например: "черный список",
"VIP-клиент" и т.п.  

## Общие принципы  
### Пользовательская активность  
После регистрации и авторизации пользователь загружает список контактов получателей, создает "тело рассылки" - 
письмо, создает рассылку, указав получателей, рассылаемое сообщение и даты возможного начала и окончания рассылки.  
Рассылки запускаются "вручную", при нажатии на кнопку "Запустить" на странице конкретной рассылки. До запуска рассылки она может
быть отредактирована, запущенные и завершенные рассылки не могут редактироваться. При каждом отправлении
в базу данных поступает отчет об успешности, на основании данных отчетов формируется статистика сервиса.  

### Реализация процессов  
На страницах "CreateView" пользователь создает объекты моделей Mailing, Message, Recipient,
соответственно рассылок, писем, получателей. Рассылки и письма строго связываются с автором - авторизованным пользователем.
Получатели связываются с пользователем отношениями "Многие ко многим", таким образом, загружаемая информация о получателе
уже может быть в базе данных, и пользователю дается возможность ею пользоваться.  
Запуск и остановка рассылок осуществляется благодаря брокеру кеширования Redis. При запуске определенный рассылки в кеше создается
соответствующий ключ, содержащий значение статуса выполнения "continue". "Время жизни" ключа заканчивается одновременно
с указанной датой завершения рассылки. Перед каждой отправкой письма значение проверяется. Если ключ не найден или его значение
равно "stopped" следующее письмо уже не отправляется. После естественного или принудительного завершения рассылки формируется
insert-запрос в базу данных, в котором в нее передается список объектов Attempt, содержащих информацию о каждой отправке.
При принудительной остановке рассылки значение ее ключа в кеше изменяется на "stopped", что прерывает цикл
функции отправки писем. После изменения статуса рассылки с "Создана" на "Запущена" или "Завершена" она не может быть
отредактирована или запущена повторно. При использовании Celery, рассылка происходит в фоновом режиме, пользователь
перенаправляется на соответствующую страницу и видит сообщение, что рассылка запущена. В другом случае, вероятнее всего
пользователь, не дожидаясь окончания рассылки переходит на другую страницу или обновляет данную, и видит, что ее статус
сменился на "запущена". Функция рассылки также продолжает работать в оперативной памяти сервера, письма уходят и
формируется отчет об отправках, но при завершении работы контроллера перехватывается ошибка BrokenPipeError.
Осуществление рассылки - принудительно замедленный процесс, это связано с тем, что SMTP-сервер, с помощью которого
происходит отправка писем, устанавливает ограничение количества отправок в единицу времени и может заблокировать аккаунт приложения.
